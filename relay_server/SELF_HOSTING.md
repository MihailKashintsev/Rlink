# Свой relay-сервер для Rlink

Rlink работает через BLE-mesh + relay-сервер. Relay нужен для доставки
сообщений, когда собеседники не рядом физически (интернет-режим) — и для
офлайн-очереди, пока адресат не в сети. Можно поднять свой сервер вместо
официального: приложение это уже умеет (Настройки → Сеть → «Свой
relay-сервер»), никаких изменений в самом приложении не требуется.

**Что даёт свой relay**: сообщения, presence (кто онлайн), офлайн-очередь.
**Чего НЕ даёт** (сознательно — это отдельные, привязанные к официальной
инфраструктуре сервисы, self-host-версия их не реализует): звонки через
TURN, платежи Premium, перевод текста, каталог музыки. Всё это останется
работать через официальный сервер — при недоступности своего relay
приложение всегда откатывается на него (см. `RelayService._urlsToTry` в
`lib/services/relay_service.dart`).

## Шаг 1 — поднять сервер

```bash
cd relay_server
cp .env.example .env
# Минимум для базового relay: сгенерировать RELAY_ADMIN_HASH (нужен для
# админ-панели в приложении — 16 тапов по экрану «О проекте»). Остальные
# переменные (VAPID/OAuth/YooKassa/TURN) можно оставить пустыми — это
# опциональные фичи, без них relay работает как чистый message-transport.
echo -n "ВашПарольАдмина" | shasum -a 256 | awk '{print $1}'
# впишите результат в .env как RELAY_ADMIN_HASH

docker compose up -d --build relay
```

Проверка, что сервер жив:
```bash
curl http://localhost:8080/health
```

## Шаг 2 — TLS (обязательно для web-версии приложения)

Мобильные и десктопные сборки могут подключаться и по `ws://` напрямую, но
**web-версия так не сможет** — браузер блокирует незащищённый WebSocket с
HTTPS-страницы (mixed content). Нужен `wss://`, то есть TLS-терминация
перед relay. Самый простой вариант — Caddy с автоматическим HTTPS:

```bash
docker run -d --name rlink-caddy -p 80:80 -p 443:443 \
  -v $(pwd)/Caddyfile:/etc/caddy/Caddyfile \
  --network relay_server_default \
  caddy:2
```

(`--network relay_server_default` assumes you ran `docker compose` from a
folder literally named `relay_server` — Compose names the network after the
folder. If it doesn't connect, run `docker network ls` and use the network
that has "relay" in its name.)

`Caddyfile`:
```
your-domain.example {
  reverse_proxy relay:8080
}
```

Без своего домена подойдёт `<ваш-ip>.nip.io` (wildcard DNS на IP) — именно
так устроен официальный сервер (`185.244.172.90.nip.io`).

## Шаг 3 — указать relay в приложении

Настройки → Сеть → «Свой relay-сервер» → `wss://your-domain.example`.
Приложение проверит доступность при следующем подключении и покажет статус
в том же разделе («Диагностика связи»); если сервер недоступен —
автоматически откатится на официальный, доставка не остановится.

## А если у собеседника нет своего relay?

Всё работает и так. Приложение при настроенном своём relay всегда держит
ещё одно лёгкое соединение с официальным сервером — специально для тех,
кто свой relay не настраивал. Ничего дополнительно делать не нужно, это
уже встроено (см. `lib/services/secondary_relay_link.dart`).

**Ограничение**: если у ОБОИХ собеседников СВОИ, РАЗНЫЕ relay (ни один —
официальный) — они пока не достучатся друг до друга. Между произвольными
серверами (не через официальный) полноценной федерации нет.
